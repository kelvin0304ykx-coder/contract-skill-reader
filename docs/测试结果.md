# 读者包本轮测试结果

本报告记录0.1.0-review读者包的三项独立测试。正式0.1.0保留相同的核心Skill、引用、校验器、虚构合同及委托示例；仅增加MIT许可、下载说明与版本记录，并将辅助工具写入的版本号更新为0.1.0。未把此前现有版/拟分享副本的输出当成这次结果，也未因文档发布重复运行审查任务。

## 实际隔离范围

- 同一Windows宿主上的全新Python 3.12.10虚拟环境，system-site-packages关闭；按requirements从头安装文档依赖，预检通过。
- 独立Codex配置和任务目录；原生加载器及模型可见提示均确认仅启用读者版合同Skill。个人Skill、插件、MCP及全局项目规则未进入这些任务。
- 沿用本机已安装的Codex CLI和有效模型登录进行真实调用，登录信息未进入包。测试临时认证链接已经移除。
- 这不是虚拟机、容器、另一台电脑或新账号登录测试。Docker引擎未运行，没有为测试启动、安装或改动Docker。
- 隔离任务未配置法律原文渠道及自动渲染器；正文/商业分析仍继续，效力相关命题明确列为需检索确认。

## 三种委托的实际结果

| 委托 | 实际耗时 | 执行状态 |
|---|---|---|
| 代表乙方审改 | 962.329秒 | 正常结束，原件与Skill哈希未变 |
| 未说明代表方整理 | 585.703秒 | 正常结束，原件与Skill哈希未变 |
| 乙方签署前核对 | 416.437秒 | 正常结束，原件与Skill哈希未变 |

三项全部自然结束，无超时、无续跑。运行并发且没有严格控制效率对照，不从耗时推出提速结论。

代表乙方审改：生成一份带真实插入/删除修订及批注的DOCX和一份条款修改理由，共12组事项，11组含正文修订、1组仅批注。110个XML修订节点、13个批注不等于110/13个法律问题；组数也不是固定标准答案。

未说明代表方：先要求明确甲方/乙方立场，整理双方方向、现有事实和缺失材料，未生成合同修订稿。

乙方签署前核对：清单分开2项材料、9项正文问题和3处签署栏位，合同未修改，未无条件放行。具体条数只是这次输出，不要求读者复现同样数量。

## 文件实际验收

最终修订稿的事项身份、0结构错误、0整段替换及条款/理由对应检查通过；3项警告均为原有双方盖章和日期留白。修改映射覆盖实际全部修订及批注，理由绑定当前文件哈希；拒绝修订后逐段文字还原原稿。

三项任务结束后，主任务另用WPS Writer 12.0 build12.1.0.23542只读打开哈希一致的最终稿快照，分别导出全部标记和修订后视图，共4页已逐页检查，无截断。批注全文另从实际DOCX读取。此步骤与隔离任务内的文本/结构检查分开，未把结构校验冒充版面验收；修订后视图仍有批注高亮，不是清洁签署稿。Microsoft Word界面未验证。

最新辅助工具还实际检查了：新建练习、拒绝覆盖已有目录、只读提取原文、拒绝损坏DOCX，原件均未变。两项拒绝是保护行为，不算审查任务失败。

仅一个合成维护合同、三种委托，不证明其他合同准确率、批量稳定性或复杂历史修订/扫描件兼容性。macOS/Linux、新电脑安装及Microsoft Word界面未实测。

附件、真实邮箱、授权和新增商业参数仍待确认；提前解除且不足整月时的报告提交、验收起点及完成比例仍可结合附件继续明确。原文检索未接入，默示验收、违约金、限责、解除与电子通知等法律命题仍待核验。这些产物是可继续审阅的候选，不是可以直接签署的定稿。
