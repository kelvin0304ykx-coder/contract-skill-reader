# 中文上手说明

## 先下载完整包

打开[公开仓库](https://github.com/kelvin0304ykx-coder/contract-skill-reader)，选择 **Code → Download ZIP**，或使用[完整ZIP下载链接](https://github.com/kelvin0304ykx-coder/contract-skill-reader/archive/refs/heads/main.zip)。解压后进入包含`README.md`和`requirements.txt`的目录，再执行下面命令。不要只下载SKILL.md：引用、校验脚本、工具和示例需要一起保留。

本包采用MIT，完整条款见[LICENSE](../LICENSE)。下载不包含模型登录、法律数据库账号或文档软件。

## 先准备这三样

1. 能访问本地项目文件、运行Python并按Skill执行任务的模型工具。本次验证入口为Codex命令行；其他客户端尚未实测。
2. Python 3.11或更新版本；用独立虚拟环境安装`requirements.txt`。这一步只准备文档处理工具，不会替你取得模型或数据库账号。
3. 用来检查实际DOCX的Word、WPS或兼容软件。原文法律检索渠道如未配置，先按虚构练习的“需检索确认”边界运行，不写已经查过。

## 一、在包目录准备Python环境

Windows PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tools\reader.py doctor
```

macOS或Linux命令形式（本轮未在这两种系统实测）：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python tools/reader.py doctor
```

检查失败时先看缺少哪一项，保留输出；不要改成“已安装”继续宣称完整环境就绪。`doctor`通过仅表示Python依赖可用，不证明模型登录、法律检索和版面验收已经完成。

## 二、创建第一种练习

在包目录执行（Windows）：

```powershell
.\.venv\Scripts\python.exe tools\reader.py init --case redline --dest .\work\第一次审改
```

目标目录必须是新的，重复初始化会拒绝覆盖。工具把Skill复制到该练习的`.agents/skills/legal-contract-review-reader/`，把虚构合同和对应委托放入`原件/`，并创建`成果/`、`过程记录/`及`任务.txt`。不安装到你的全局Skill库，不改当前其他项目。

## 三、调用Skill做实际工作

从创建好的练习目录启动已安装、已登录的Codex，打开`任务.txt`并发送其内容。该任务显式指定本项目Skill路径，要求读取`原件/委托说明.md`后执行。项目Skill目录及显式`$skill-name`调用方式见[官方Skill文档](https://learn.chatgpt.com/docs/build-skills)。

告诉助手使用刚才建好的Python虚拟环境解释器，避免误用系统Python。完整练习中，先锁定母稿身份再编辑；要求修订稿、修改理由及内部对应关系来自本次真实文件。只需要清单时不要要求它顺便接受修订或重写合同。

本次委托也可以这样概括：

> 调用合同审查Skill，代表乙方审查。保留已确认的总价、服务期和巡检频次；在原结构上另存带修订DOCX，另交对应条款的修改理由。缺附件或信息就列出，不补造，不覆盖原件；新增商业条件是待确认建议。

这段话是使用示例，不代替你提供当前合同及明确委托。不要把以前任务的成果作为新样本的标准答案。

## 四、另建两种练习

```powershell
.\.venv\Scripts\python.exe tools\reader.py init --case intake --dest .\work\第二次整理
.\.venv\Scripts\python.exe tools\reader.py init --case signing --dest .\work\第三次核对
```

每次从各自目录打开新任务，分别发送该目录`任务.txt`；三种练习不共用上一次输出。intake用于立场不明的前期整理，signing只出签署核对清单，不生成修改后的合同。

## 五、验收实际文件

- 重开成果，检查主体、编号、总价、日期、频次等已确定内容是否按委托保留。
- 对照每处实际改动与修改理由，未补的附件/邮箱不能写成已经落实。
- 按Skill的身份规则运行随包校验器，错误应修正，警告逐项说明；报告不能替代条款含义判断。
- 用实际文档软件查看全部标记和修订后视图，逐页检查断行、分页、批注和签署区；拒绝修订后的文字应能回到母稿。未做版面检查就注明待验，不宣称可以直接签署。
- 保留初稿、失败报告、改后稿及最终检查记录；后续修改合同，要同步更新理由和映射。

## 遇到问题

找不到Skill：确认练习目录下存在`.agents/skills/legal-contract-review-reader/SKILL.md`，并在本目录开新任务显式指定该路径。只复制入口文件而丢掉引用/脚本，不算完整安装。

找不到Python库：使用本练习虚拟环境里的Python运行`doctor`，不要只看另一个Python的安装列表。

没有数据库或文档软件：不随意上传合同、不自动安装软件。把依赖该能力的具体环节记为待确认/待验，继续范围内可完成的整理。

复杂历史修订、表格、扫描件、受保护文件：先说明具体读写限制，保留当前原件；本次简单虚构合同通过不能证明这些格式同样适用。
