# 真实失败、诊断和修正

本页按实际发生的环节区分，不把失败索引条目数量说成独立失败次数，也不把预期拒绝当成缺陷。

| 环节 | 实际情况 | 处理与记录 |
|---|---|---|
| 打包脚本首次准备 | 新增说明先创建了目标目录，目录级保护断言拒绝继续 | 改为检查尚未创建的Skill入口，保留保护，未覆盖源或旧成果；原失败留档 |
| 嵌套依赖检查 | 一份审阅矩阵仍按名称要求私人法律检索Skill | 改为随包原文来源规范及实际可用能力；再次扫描未发现私人依赖 |
| 新Python环境 | 首次预检缺少文档库并返回失败 | 按包内requirements安装后通过；安装前/后及pip记录均保留 |
| 首次配置隔离检查 | 临时HOME仍能发现用户目录里的两个其他Skill及系统Skill | 仅修改临时配置，显式禁用非读者Skill；原生加载器和模型可见提示确认隔离修正 |
| 审改任务工具读取 | 首次PowerShell读取没有及时返回，任务终止该读取 | 改用不加载用户配置的读取方式继续；未返回的内容不当成已经读过 |
| 签署检查原件诊断 | 无候选/母稿基线的原件结构诊断返回3个签署空栏错误 | 原报告原样保留，不填造日期或改脚本放行；清单把三处栏位与材料/正文问题分别处理。这不是带基线的修订稿身份验收 |
| 签署检查内部定位 | 签署栏段落序号初稿写大一位 | 回到母稿改正记录，旧记录留存；合同未改 |
| 审改任务语义复查 | 首轮结构检查通过，但催告期限起算及理由中的跨条检索说明仍可更清楚 | 在同一任务中明确送达后起算、收窄重复说明，旧候选和原报告保留，再核对当前版本 |
| 主任务对应检查 | 独立检查器误把一基段落编号当成零基数组索引 | 核对映射生成/读取代码的实际约定后修正检查器，保留该失败；未改合同、映射或随包验收器 |

工具的两项预期拒绝也有记录：重复初始化不得覆盖已有练习，损坏DOCX不得当作有效文档继续读取。

原始记录在本地审阅目录evidence下；公开读者包只保留本说明，避免混入个人配置、宿主路径及未经整理的运行日志。上述修正没有改动正在日常使用的合同Skill。
