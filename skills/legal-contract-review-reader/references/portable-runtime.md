# 读者运行环境与DOCX处理

本包不依赖另一个私人Skill。先确认实际有模型执行环境、Python以及文档读写能力。根目录requirements.txt列出本次使用的第三方Python库；只检查正文和运行校验器可仅用标准库，编辑复杂文件须有经过验证的实现。

## 文件与命令

- 从项目根目录运行`python tools/reader.py read 原件/维护服务合同.docx`可读取正文、页眉页脚、脚注尾注和批注文本；输出只用于核对，图片或扫描文字不自动OCR。
- 原件只读；成果和过程记录另存。编辑前按matter-identity-gate.md锁定母稿身份和SHA256。
- `python-docx`适合读取和新建简单文档，但不能假设它重存既有修订、批注、复杂字段时毫无损失。不要把原文段落全删再插入整段新文。
- 精准修订可使用ZIP与lxml编辑OOXML：保留原包、段落属性、运行格式、未修改文字、关系和历史修订；只有变化的短语/句子放入`w:del`及`w:ins`，删除文字用`w:delText`，新作者为“审阅人”。不要只打开trackRevisions设置后保存普通替换文本并称为修订。
- 新批注须有comments部件、正确关系及锚点；完整关系由随包只读校验器检查。无法安全处理嵌套域、合并表格或复杂既有修订时，保留原件并具体说明限制，换可靠编辑工具；不能静默重建。
- 写入后用独立读取方式核对当前可见文本、实际修订和批注。拒绝新修订后的文字应还原对应母稿；未改动的历史修订作者保留。

## 结构检查

从实际Skill目录调用脚本，路径中的尖括号必须替换为本次真实路径：

```text
python <skill-dir>/scripts/validate_contract_ooxml.py <成果.docx> --baseline <原件.docx> --identity <过程记录/身份.json> --require-identity --mode review --json
```

身份从母稿建立，不从成果反推；修改理由及映射绑定当前输出哈希。保持所有错误和警告的真实报告，不能改验收期望来绕过失败。

## 版面检查是独立步骤

读者提供本机可用的Word、WPS或兼容软件，实际打开成果、查看全部修订标记与修订后视图，并逐页检查。也可用已安装的兼容渲染器导出PDF/页图；若导出不显示批注全文，批注还要从原文件另读。不得把修订后视图当作已接受修订的清洁稿。

缺渲染器时先保存候选和真实状态“版面待验”；保留已完成的文本、结构和对应检查，不宣称可以正式交付或签署。禁止自行安装软件、改系统或上传客户合同到转换网站来绕过缺口。

## 外部能力

原文法律检索按research-sources.md执行，数据库、账户、MCP和其他Skill不随包提供。没有检索渠道也可以完成合同事实、商业安排和联动条款的本地分析；效力/法条命题逐点标为需核验，不把检索缺失说成条款已合法或无效。
